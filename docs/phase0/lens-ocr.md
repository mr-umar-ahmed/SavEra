# Phase 0 review lens: ocr

_Independent reviewer output (verified against the local PG15 + TimescaleDB 2.28.3 where it says so). Decisions adopted are recorded in ../PHASE0_PLAN.md._

#### LENS: ocr

[HIGH] 'Label -> nearest numeric on same/next line' over GCV raw text mis-pairs fields on tabular bills (column-major output)
  detail: SPEC.md L520-523 says 'GCV returns raw text. Parse it with regex'. For two-column key/value layouts (BESCOM online PDF/printouts, MSEDCL A4 bills, TNEB portal printouts) GCV's `fullTextAnnotation.text` frequently emits blocks column-major: a run of label-only lines followed by a run of value-only lines, e.g.

  Units Consumed
  Total Bill Amount (Rs)
  Bill Amount if paid after due date
  312
  2,145.00
  2,190.00

A same/next-line heuristic pairs 'Units Consumed' with the next line (a label, no number) -> kWh missing, or with whatever number happens to follow -> wrong kWh with a high score. Spot-billing receipts (thermal, single column 'Label : value') are fine, but the Phase-1 acceptance test 'BESCOM bill image -> kWh +/-2' will pass on fixtures and fail on real portal PDFs/screenshots.
  rec: Parse on reconstructed rows, not on GCV's text string. Request `DOCUMENT_TEXT_DETECTION` and take words from `responses[0].fullTextAnnotation.pages[].blocks[].paragraphs[].words[]` (word text = join of `symbols[].text`; box = `boundingBox.vertices`). Build a `Word(text, x0, y0, x1, y1, conf)` list and cluster into rows: sort by vertical centre, start a new row when |cy - running_mean_cy| > 0.5 * median word height, sort each row by x0, join with single spaces; insert a ' | ' column break where the horizontal gap > 3x median char width. Tesseract gives the same via `pytesseract.image_to_data(output_type=Output.DICT)`, so one `parse_bill(rows)` serves both engines. Label-proximity on rows: (1) same row, first numeric token after the label and before the next label span (weight 1.0); (2) next row, if that row has no label spans, the numeric token whose x-centre is closest to the label's x-span (0.8; 0.6 when no boxes/text mode); (3) column-major rescue: when a run of N consecutive label-only rows is followed by a run of M value-only rows and N == M, zip them positionally (0.7), else skip. Keep the plain `text.split('\n')` path as the fallback when boxes are unavailable (pdf text layer) and unit-test it with an explicit column-major fixture (see test plan).

[HIGH] Date digits and ID numbers pass the sanity bounds and will be selected as kWh/amount unless masked before numeric search
  detail: With bounds kWh 1-5000 and amount 10-100000, these all qualify as candidates: '2026' from 'Bill Date : 05-03-2026' (2026 kWh), '03' and '05' (units), '560034' (Bengaluru PIN, a valid amount), 'Bill No 2603123456' fragments, 'Sanctioned Load : 3 KW' (3 units), 'Meter No 45678912', slab rows like '101-200 units @ 5.20 = 520.00'. Sanity bounds alone do not protect against these; the spec's regex description has no tokenization order.
  rec: Fixed per-row pipeline before any value search: (a) normalise OCR confusions only inside digit-heavy tokens (>=50% digits): O/o->0, I/l/|->1, S->5, B->8; (b) find and MASK date spans (all date regexes below) and ranges; (c) find and mask ID segments: any numeric token with >=7 digits and no decimal point, and the first numeric token after an ID label `\b(RR\s*No|Account\s*ID|Consumer\s*(?:No|Number)|Meter\s*(?:No|Number|Sl)|Bill\s*No|Service\s*(?:No|Connection)|Receipt\s*No|Mobile|Phone|PIN(?:code)?|GST(?:IN)?|Bill(?:ing)?\s*Unit|PC|Cycle)\b`; (d) drop the whole row from kWh/amount candidacy if it matches a rate/slab pattern `\d+\s*-\s*\d+\s*units|@|per\s*unit|/unit|/kwh|\brate\b|\bslab\b|x\s*\d+(?:\.\d+)?\s*=`; (e) exclude unit-ish false friends via `\bKW\b|KVA|KVAH|sanctioned|connected\s*load|contract(?:ed)?\s*demand|solar|export|import|free\s*units?|chargeable\s*units?`; (f) only then run `NUM = r"-?\d{1,3}(?:,\d{2,3})+(?:\.\d{1,2})?|-?\d+(?:\.\d{1,2})?"` (strip commas; Indian lakh grouping 1,23,456.00 is accepted by the first alternative), strip `Rs|Rs\.|₹|INR|/-`. Bounds: kWh 1-5000 (0 allowed but forces needs_review), amount 10-100000, readings 0-999999 (<=8 digits), MF 1-1000 only when explicitly labelled.

[HIGH] Amount-payable extraction: 'Amount after due date', 'Energy Charges', 'Arrears', 'Rebate' are all in-bounds and often larger/closer than the real payable
  detail: Spec says 'look for Amount Payable, Net Amount'. Every Indian bill also prints 'Amount after due date' / 'Bill Amount if paid after due date' (bigger than payable), 'Energy Charges' (close to payable), 'Total Current Bill' (pre-arrears), 'Arrears', 'Interest', 'Security Deposit', 'Rebate'/'Prompt Payment Discount'. A generic 'amount' regex with nearest-number picks any of them. Also 'Total' matches 'Total Consumption' (units) as an amount.
  rec: Weighted label table (IGNORECASE, applied to the row segment), pick max weight then earliest occurrence:
  1.00  net\s*amount\s*payable | total\s*amount\s*payable | amount\s*payable | net\s*payable | net\s*bill\s*amount | total\s*bill\s*amount | rounded\s*bill\s*amount | bill\s*amount\s*payable
  0.85  amount\s*due | net\s*amount | total\s*amount | current\s*bill\s*amount | bill\s*amount
  0.60  total\s*current\s*bill | grand\s*total
  0.40  \bamount\b | \btotal\b | \bamt\b   (TNEB receipts often just say 'Amount')
Exclusion: a label segment whose preceding 40 chars on the row contain `after\s*due|if\s*paid\s*after|late|arrear|interest|deposit|rebate|discount|previous\s*balance|credit|adjust|energy\s*charge|fixed\s*charge|wheeling|FAC|FPPCA|duty|tax\b|surcharge|subsidy` scores 0. Tie-break for equal weight: prefer the later row (totals sit at the bottom). Utility specifics: BESCOM -> 'Net Amount Payable' / 'Amount Payable' / spot-bill 'NET PAYABLE'/'TOT AMT'; MSEDCL -> 'Total Bill Amount (Rs)' / 'Net Bill Amount' / 'Rounded Bill Amount'; TNEB -> 'Amount' / 'Total Amount' / 'Amount Payable'. Accept decimals with 1-2 places; if two strong labels disagree, keep the higher-weight one and add warning AMOUNT_AMBIGUOUS (-5 confidence).

[HIGH] Date parsing must be day-first and format-explicit; billing-period derivation order is unspecified
  detail: Spec: 'look for date ranges, month names'. `dateutil.parser.parse('05/03/2026')` returns May 3 (month-first) -> billing periods silently shifted by months, and DB CHECK is not violated so it is never caught. Bills use DD-MM-YYYY (BESCOM), DD.MM.YYYY (MSEDCL), DD/MM/YYYY (TNEB), DD-MMM-YY, 'MAR-2026'/'Mar'26'/'03/2026' month tokens, and TNEB is bimonthly (60-day period) with often only the present 'Assessment Date' printed.
  rec: Explicit regexes, no dateutil:
  DMY   = r"\b(\d{1,2})[-/. ](\d{1,2})[-/. ](\d{4}|\d{2})\b"
  DMONY = r"\b(\d{1,2})[-/. ]?(JAN|FEB|MAR|APR|MAY|JUN|JUL|AUG|SEP|SEPT|OCT|NOV|DEC)[A-Z]*[-/. ,]?'?(\d{4}|\d{2})\b"
  MONY  = r"\b(JAN|FEB|MAR|APR|MAY|JUN|JUL|AUG|SEP|SEPT|OCT|NOV|DEC)[A-Z]*[-/ ,.]?'?(\d{4}|\d{2})\b"   # MAR-2026, MARCH 2026, Mar'26
  MMYYYY= r"\b(0?[1-9]|1[0-2])[-/](\d{4})\b"
  ISO   = r"\b(\d{4})-(\d{2})-(\d{2})\b"
  RANGE = r"(<DATE>)\s*(?:to|-|–|—|till|upto|through)\s*(<DATE>)"
Two-digit year -> 2000+yy. Validate via `date()` in try/except; reject dates outside [today-3y, today+60d]. Date labels: bill_date `bill\s*date|date\s*of\s*bill|issue\s*date|bill\s*dt`; due_date `due\s*date|pay\s*by|last\s*date|due\s*dt`; present reading date `(present|current|curr|pres|closing)\s*(reading|rdg|read)?\s*(date|dt)|reading\s*date|date\s*of\s*reading|assessment\s*date|asst\s*dt`; previous reading date `(previous|prev|last|opening)\s*(reading|rdg|read|assessment)?\s*(date|dt)`; period `bill(?:ing)?\s*(?:period|month)|month\s*/?\s*year|for\s*the\s*month|billing\s*cycle`. Derivation order for billing_period_start/end with period_source: (1) explicit RANGE near a period label -> 'explicit_range'; (2) previous reading date -> present reading date -> 'reading_dates'; (3) month token (MONY/MMYYYY) near period label, else the only month token in the header -> calendar month 'bill_month'; (4) utility==tneb and only one assessment/reading date -> [end-61d, end] 'inferred_bimonthly'; (5) bill_date only -> [bill_date-30d, bill_date] 'inferred_from_bill_date'. Cross-checks (warnings, -5 each): start < end; period length 20-70 days (else -10); bill_date >= end - 2d; due_date > bill_date. Same-row segmentation handles 'Bill Date : 05-03-2026  Due Date : 20-03-2026'.

[HIGH] Upload -> confirm UX conflicts with the 'OCR runs in BackgroundTasks, <400 ms' rule; route contract must be defined now
  detail: SPEC L515 wants 'Bill photo upload -> OCR -> extracted data shown for user confirmation -> save', while Agent Operating Rules L657 say OCR parsing runs in BackgroundTasks and POST /readings/* returns <400 ms. GCV takes 1-4 s, Tesseract 3-15 s, so a synchronous upload endpoint cannot meet the rule, and a BackgroundTask has nowhere to put the result unless a job record exists. The API contract section (L391-395) is empty, so this decision is unmade.
  rec: Job + polling. `POST /api/v1/bills/upload` (multipart `file`, image/jpeg|png|webp|pdf, <=10 MB): validate MIME by magic bytes, run `preprocess_image` in `asyncio.to_thread`, upload the JPEG to private Supabase Storage bucket `bills` at `{user_id}/{job_id}.jpg` with the service key, INSERT ocr_jobs, `background_tasks.add_task(run_ocr_job, job_id)`, return 202 `{job_id, status:'pending'}`. `GET /api/v1/bills/jobs/{job_id}` (WHERE user_id = caller) -> `{status:'pending'|'done'|'failed', extraction: OcrExtraction|null}`. Saving stays on `POST /api/v1/readings/electricity` with `source:'ocr'`, `bill_image_url` (store the storage object path, sign on read), `ocr_job_id` optional; the server re-validates bounds on the user-confirmed values, so OCR never writes electricity_readings directly. Table (needs plan-phase sign-off as a schema addition):
CREATE TABLE ocr_jobs (id UUID PRIMARY KEY DEFAULT gen_random_uuid(), user_id UUID REFERENCES users(id) ON DELETE CASCADE, status TEXT NOT NULL DEFAULT 'pending', engine TEXT, image_path TEXT NOT NULL, extraction JSONB, raw_text TEXT, confidence INTEGER, needs_review BOOLEAN, error_code TEXT, created_at TIMESTAMPTZ DEFAULT NOW(), finished_at TIMESTAMPTZ);
CREATE INDEX idx_ocr_jobs_user ON ocr_jobs(user_id, created_at DESC);
Frontend `BillUploadForm.tsx` polls every 1.5 s up to 40 s, then shows kwh / period / amount editable, highlights fields with field_confidence < 70, and on needs_review shows the banner 'We couldn't read this bill confidently - please check the numbers' plus raw_text in a collapsible. Fallback alternative if sign-off refuses the table: synchronous endpoint with a 15 s budget, documented as an explicit deviation.

[MEDIUM] Tesseract fallback trigger is under-specified (spec: only 429) and the missing-binary path is undefined; dev machine has no tesseract
  detail: Spec L525 triggers only on 429. GCV can also fail with 403 (key restricted / billing disabled / API not enabled), 5xx, network timeouts, and - importantly - HTTP 200 with a per-image error inside the body (`responses[0].error.code` 8 RESOURCE_EXHAUSTED, 7 PERMISSION_DENIED, 3 INVALID_ARGUMENT). `pytesseract.image_to_string` raises `TesseractNotFoundError` when the binary is absent (true on this Windows box and in a default python:slim image); an unhandled raise turns into a 500 and violates 'never silently fail'. Tesseract without kan/mar/tam traineddata emits garbage for the Indic lines, which is harmless because labels are English, but `-l eng` must be forced.
  rec: Call GCV via REST with httpx (`POST https://vision.googleapis.com/v1/images:annotate?key={GCV_API_KEY}`, feature DOCUMENT_TEXT_DETECTION, `imageContext.languageHints:['en']`, timeout 15 s) - no `google-cloud-vision`/grpc dependency. Fallback to Tesseract when: GCV_API_KEY unset/empty; HTTP 429, 403, 500-504; `httpx.TimeoutException`/`ConnectError` after one retry with 1 s backoff on 5xx/timeouts only (never retry 429/403); or body `responses[0].error.code in (7, 8, 13, 14)`. Do NOT fall back on 400 / body code 3 (bad image) -> job failed with error_code='invalid_image'. Tesseract path: `pytesseract.pytesseract.tesseract_cmd = settings.TESSERACT_CMD` if set (Windows default `C:\Program Files\Tesseract-OCR\tesseract.exe`); guard with `shutil.which(cmd)`; run `pytesseract.image_to_data(img, lang='eng', config='--psm 6 --oem 1', timeout=20, output_type=Output.DICT)` inside `asyncio.to_thread`; catch `TesseractNotFoundError`, `TesseractError`, `RuntimeError` (timeout) -> return `OcrExtraction(engine='none', confidence=0, needs_review=True, raw_text='', warnings=['OCR_UNAVAILABLE'])`, job status 'done' with error_code='ocr_unavailable', HTTP 200 on poll so the form drops to manual entry. Import pytesseract lazily inside a try so the backend boots without it. Dockerfile: `apt-get install -y --no-install-recommends tesseract-ocr tesseract-ocr-eng` (~150 MB; open question whether to include). Record `engine` on every result.

[MEDIUM] Confidence score (0-100) and needs_review semantics are undefined in the spec
  detail: Spec says '<70% -> return raw text and flag for manual review' but never defines how the percentage is computed; without a deterministic rubric the threshold is untestable and the frontend cannot highlight individual fields.
  rec: Additive rubric, clamp 0-100, deterministic and unit-tested:
  kWh (max 50): labelled & in-bounds 50 | derived from readings only 40 | bare 'units'/'kwh' token only 25 | none 0
  period (max 25): reading_dates / explicit_range 25 | bill_month 18 | inferred_bimonthly 12 | inferred_from_bill_date 8 | none 0
  amount (max 15): strong label (weight 1.0) 15 | weak label 10 | none 0
  utility header detected: +10
  bonus: kWh label and derived readings agree +/-2 -> +10
  penalties: KWH_MISMATCH -20; engine=='tesseract' -10, and a further -10 if mean Tesseract word conf of chosen tokens < 60; GCV symbol confidence of a chosen kWh/amount token < 0.6 -> -10; period length outside 20-70 days -10; AMOUNT_AMBIGUOUS -5; each failed date cross-check -5; raw text < 40 chars -> total 0.
  needs_review = confidence < 70 OR kwh is None OR billing_period_start is None OR kwh == 0.
Worked values: clean BESCOM spot bill 50+25+15+10+10 -> 100; MSEDCL with 'Bill Month' only 93; TNEB single assessment date 87; readings-only + bill-date-only 68 -> review. Expose `field_confidence: {kwh, period, amount}` (each 0-100 = component/max*100) so BillUploadForm can highlight per field. Always return raw_text (cap 20 KB) and `warnings[]`; never raise out of run_ocr_job - every exception becomes a 'done' job with engine='none'.

[MEDIUM] No image preprocessing spec: EXIF rotation, size, grayscale, PDF bills and HEIC uploads are unhandled
  detail: Phone photos carry EXIF orientation; without `exif_transpose` the pixels are sideways (GCV tolerates it, Tesseract does not). 12-MP JPEGs (4-8 MB) waste 3G bandwidth (spec is mobile-first) and slow GCV. MSEDCL and BESCOM portal bills arrive as PDFs with a text layer - OCR is unnecessary and worse than reading the layer. iPhones default to HEIC, which Pillow cannot open without pillow-heif.
  rec: Server `preprocess_image(bytes) -> (jpeg_bytes, PIL.Image)`: `Image.open` -> `ImageOps.exif_transpose` -> `.convert('L')` (grayscale) -> `thumbnail` so the longest side <= 2000 px (never upscale for GCV) -> `ImageOps.autocontrast(cutoff=1)` -> save JPEG quality 85 (typically < 1 MB; GCV limit is 20 MB). Tesseract-only extras: upscale x2 with LANCZOS when longest side < 1500 px (target x-height >= 30 px); no OpenCV/deskew in MVP. Validate MIME by magic bytes (JPEG/PNG/WebP/PDF), reject > 10 MB and > 40 MP. PDF: `pypdf` `extract_text()` on page 1 -> if >= 200 chars and a utility header matches, parse it with engine='pdf_text' (text-only row path, no boxes); else render is unavailable without poppler, so send the PDF to GCV `files:annotate` (`inputConfig.mimeType:'application/pdf'`, pages [1]) which returns the same fullTextAnnotation shape. HEIC: either add `pillow-heif` and register the opener, or reject with error_code='unsupported_format' and a UI hint; note iOS Safari converts HEIC to JPEG when the input has `accept="image/jpeg,image/png"`. Client: BillUploadForm resizes to <= 2000 px on a canvas at JPEG 0.85 before upload.

 - Use the weighted label tables given above for kWh, amount, readings and dates, with exclusion contexts (after-due-date, arrears, energy/fixed charges, free/chargeable units, KW/KVA/sanctioned load) and OCR-tolerant character classes.
