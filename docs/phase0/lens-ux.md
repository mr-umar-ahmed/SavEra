#### LENS: ux

[BLOCKER] Vitest 5, jsdom 30 and jest-dom 7 cannot run on this machine's Node 20.20
  detail: npm engines (verified via `npm view`): vitest@5 requires node ^22.12 || ^24 || >=26, jsdom@30 requires ^22.22.2 || ^24.15, @testing-library/jest-dom@7 requires >=22. On the scaffold, a plain `npm i -D vitest jsdom @testing-library/jest-dom` silently resolved to vitest@4.1.11, jsdom@29.1.1, jest-dom@6.9.1 because npm filters candidates by the running Node. The brief's 'Vitest 5' target is therefore unreachable without a Node upgrade.
  rec: Either (a) install Node 24 LTS (`winget install OpenJS.NodeJS.LTS`, then re-open the shell) and use vitest@^5 jsdom@^30 jest-dom@^7, or (b) pin `vitest@^4.1 jsdom@^29 @testing-library/jest-dom@^6.9` now; the vitest.config.mts, setup file and the three component tests are identical for both, and (b) was verified green (4/4 tests) in a probe on this box.

[HIGH] @vitejs/plugin-react@6 cannot be installed next to shadcn 4 with npm (ERESOLVE) — and is not needed
  detail: npm ERESOLVE report: @vitejs/plugin-react@6.1.1 → peerOptional @rolldown/plugin-babel → @babel/plugin-transform-runtime@8.0.0-rc.4 → peer @babel/core@^8.0.0-rc.4, which conflicts with @babel/core@7.29.7 pulled in by `shadcn@^4.21.0` (shadcn 4 adds itself as a runtime dependency for `@import "shadcn/tailwind.css"`). Vite 8's built-in oxc transform compiles .tsx with the automatic JSX runtime from tsconfig `jsx: react-jsx`; the probe passed all RTL + recharts + shadcn Button tests with no React plugin at all. Vite 8 also warns that `vite-tsconfig-paths` is superseded by `resolve.tsconfigPaths: true`.
  rec: Do not install @vitejs/plugin-react or vite-tsconfig-paths; use `defineConfig({ resolve: { tsconfigPaths: true }, test: { environment: 'jsdom', setupFiles: ['./vitest.setup.ts'] } })`. Never use `--legacy-peer-deps`.

[HIGH] shadcn 4 CLI flags differ from older docs: `-p radix-nova` is invalid, Base UI is the default library, tooltips need a root provider
  detail: Probe output: `Invalid preset: radix-nova. Available presets: nova, vega, maia, lyra, mira, luma, sera, rhea`; the library is chosen with `-b base|radix|aria` (default base = Base UI). `init -b radix -p nova -y` succeeded non-interactively and wrote components.json style `radix-nova`, deps `shadcn`, `radix-ui` (unified package), `cn`, `class-variance-authority`, `lucide-react@1.48`, `tw-animate-css`; `add` printed that the app must be wrapped in `<TooltipProvider>`; `sonner.tsx` imports `useTheme` from next-themes; `field`/`input-group` pull `textarea`.
  rec: Use `npx -y shadcn@4.21.0 init -b radix -p nova -y` then one `add` call with `-y -o`; wrap the root layout in `ThemeProvider` (next-themes) + `TooltipProvider`; mount `<Toaster />` once.

[HIGH] create-next-app 16: `--reset` is interactive, `--yes` silently reuses saved preferences, no `--turbopack` flag, and it writes CLAUDE.md/AGENTS.md into frontend/
  detail: Probe: `--reset` printed a prompt ('Would you like to reset the saved preferences? No / Yes'). `--yes` means 'use saved preferences or defaults for unprovided options', so an omitted flag (e.g. --src-dir) can be flipped by a previous run on the machine. There is no `--turbopack` flag any more (Turbopack is default; `--rspack` exists). The scaffold pins react 19.2.8 (not 19.3), @types/node ^20, and generates `frontend/CLAUDE.md` + `AGENTS.md`, `next.config.ts`, `postcss.config.mjs` with @tailwindcss/postcss, and Next 16 route types (`LayoutProps<'/'>`).
  rec: Pass every option explicitly and never `--src-dir` (spec wants root-level app/, components/, lib/); delete the generated frontend/CLAUDE.md so the repo-root CLAUDE.md governs; keep react 19.2.8 as scaffolded.

[HIGH] Spec folder tree is missing the files Next 16 + @supabase/ssr auth actually needs
  detail: Next 16 renamed middleware.ts → proxy.ts (named export `proxy`, Node runtime, `runtime` config forbidden). A single `lib/supabase.ts` cannot serve browser, server and proxy clients (server.ts imports next/headers and would break in client bundles). Magic link + signup confirmation with SSR need `app/auth/confirm/route.ts` (`verifyOtp({ type, token_hash })`) and Supabase email templates rewritten to `{{ .SiteURL }}/auth/confirm?token_hash={{ .TokenHash }}&type=…`. Unlike the Supabase example where `/` is public, SAVERA's `/` is the protected dashboard. `getSession()` must never gate rendering; `getClaims()` (present in supabase-js) is the verified check.
  rec: Add `frontend/proxy.ts`, `lib/supabase/{client,server,proxy}.ts`, `app/auth/confirm/route.ts`, `app/(auth)/actions.ts`; record the deviation from `lib/supabase.ts` in the Phase 0 plan.

[HIGH] Mobile-first shell and Day-1 onboarding have no home in the spec's route tree
  detail: `(dashboard)/layout.tsx` is annotated 'nav sidebar' only, but every card must work at 390px and a sidebar steals width; Phase 1 requires an onboarding flow of max 2 screens but no route exists for it.
  rec: Make `(dashboard)/layout.tsx` an AppShell with a 5-tab bottom bar (<768px) and a 240px sidebar (≥768px); add `app/(onboarding)/onboarding/page.tsx` outside the tabbed shell, gated by `profile.onboarding_complete`.

[MEDIUM] Dashboard <1.5s on 3G is unreachable if recharts loads on the home page
  detail: recharts 3 adds roughly 100–150 KB gzipped plus React reconciliation; the dashboard needs only a gauge, a progress bar and cards, none of which need recharts. Fonts are the other budget risk (Inter variable with opsz is large).
  rec: Keep recharts strictly on /electricity, /water (and /supervisor) inside `next/dynamic(..., { ssr: false })` client components; hand-write the gauge as SVG; load Bricolage Grotesque (variable, latin, opsz only) + Inter (static 400/500/600/700, latin) via next/font; render pages as Server Components with `loading.tsx` streaming.

[MEDIUM] Contrast facts that constrain the palette (computed, WCAG 2.x formula)
  detail: Vivid greens fail on white: #16C47F 2.27:1, #22C55E 2.28:1, #0E8A5A 4.37:1 (text fails); #0B7A52 gives 5.36:1 with white text. sky-500 #0EA5E9 is 2.77:1 (fails 3:1 graphics); sky-600 #0284C7 is 4.10:1. amber-500 #F59E0B is 2.15:1; amber-600 #D97706 is 3.19:1 (graphics only); amber-700 #B45309 is 5.02:1 on white and 4.65:1 on #FFF6DB. No yellow reaches 3:1 as a fill on white (yellow-600 #CA8A04 = 2.94:1), so a yellow status can never be colour-only. Electricity amber and warning amber would collide if both appear as fills. lucide-react 1.x removed `Home` and `AlertTriangle` (use `House`, `TriangleAlert`).
  rec: Adopt the token set in the decisions; carry status by StatusPill (icon + text + soft background), never by fill alone; use resource colour for bars and status colour only in pills/gauge arc.

[MEDIUM] Supervisor role cannot be enforced in proxy.ts
  detail: `users.role` lives in the app DB, not in the Supabase JWT, so `getClaims()` cannot see it; proxy can only distinguish signed-in vs not.
  rec: Let FastAPI return 403 and have `app/supervisor/page.tsx` render a 'Supervisor access only' state on 403; optionally add role to `app_metadata` via a Supabase Custom Access Token Hook later (FUTURE.md).

[MEDIUM] API contract (PHASE0_PLAN.md §6) does not exist yet, so lib/api.ts is typed against proposed routes
  detail: docs/ contains only SPEC.md; the spec references docs/PHASE0_PLAN.md for the stack, §5.2, §5.5 and the route table. The frontend also needs endpoints the spec never lists: `GET /api/v1/wards` (ward selector), `profile.onboarding_complete`, and monthly aggregation of daily water readings for the 6-month chart.
  rec: Reconcile the endpoint list in the decisions with the backend plan before Phase 1; add `GET /wards` and an `onboarding_complete` flag to `GET /profile`.

[LOW] Alert types 'milestone' and 'weekly_digest' need positive-tone templates and icons; LPG refill alerts need date-first copy
  detail: The spec's tone rule covers anomalies; milestones and digests must not reuse the warning visual language, and refill alerts must lead with the predicted date, not a warning.
  rec: Use the per-type title templates and icon map in the decisions (Sparkles for milestone, CalendarDays for digest, Flame for refill).

[LOW] Push notifications: one root-scope service worker only, no prompt on load
  detail: FCM web needs `public/firebase-messaging-sw.js` registered at scope '/'; adding a Serwist offline SW (`@serwist/turbopack` 9.5.12 exists: `createSerwistRoute`, `withSerwist`, `SerwistProvider` from `@serwist/turbopack/react`) would mean two SWs competing for scope. Chrome installability no longer requires an SW, so the manifest alone makes the app installable.
  rec: Ship manifest + viewport only; register the FCM SW lazily from the Profile toggle; file Serwist offline caching in FUTURE.md.

[LOW] Do not disable pinch-zoom in the viewport export
  detail: `maximumScale: 1` / `userScalable: false` is an accessibility failure (WCAG 1.4.4) and reads as a dark pattern under the spec's 'no dark-pattern UI' rule.
  rec: Export `viewport = { width: 'device-width', initialScale: 1, viewportFit: 'cover', themeColor: [...] }` and nothing that limits zoom.
