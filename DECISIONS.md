# DECISIONS.md — deviations from `docs/MASTER_PROMPT.md` and notable choices

Format: **Decision** — reason. (Date: 2026-09-25 unless noted.)

1. **Spec files `docs/spec/01…06.md` were not supplied.** The master prompt (§5–§11) is used as the sole screen-level source of truth; concise derived spec files are authored in `docs/spec/` from the prompt so the referenced structure exists. Where the prompt says "see spec 02", the corresponding prompt section governs.
2. **Previous SavEra app was deleted; only its visual theme was kept** (dark `#050B08`/`#0A0F0D`, emerald primary, Outfit + Inter, glass cards, pill buttons, status accents). This was the explicit user instruction ("use the theme of the folder… override and delete everything").
3. **Next.js 15.5** (prompt target) replaced the previously installed Next 16.1 — fresh `npm install`, lockfile regenerated.
4. **Maps: react-leaflet 5 + OSM raster tiles** instead of MapLibre GL — lighter, no WebGL requirement, simpler dynamic import; the prompt allows either.
5. **shadcn/ui components are hand-authored** on Radix primitives (`src/components/ui`) rather than generated by the shadcn CLI, so tokens map exactly to the inherited theme. API mirrors shadcn.
6. **State model: one persisted Zustand "demo database" (`useDataStore`)** seeded from `buildSeed(demoNow)` plus small session/twin/ui stores, with an async mock API layer over it. Simpler than per-role stores and still swappable for a real backend.
7. **Auth is client-side** (persisted session + `RoleGuard` in each portal layout); no Next middleware, since there is no server session.
8. **`demoNow`** is captured once on the client and persisted; seed dates are relative to it (current LPG cylinder started `demoNow − 18 d`, previous cycles 25 d each; current electricity month = month of `demoNow`). This keeps the spec anchors (18 days used, 350 → 390 kWh) true on any date.
9. **LPG "Area A–D"** in the supervisor screens map to XYZ/ABC/DEF/GHI Colony (codes A–D) so every screen uses the same four Ward 24 areas.
10. **zod v4** (installed latest) instead of v3 — API differences are minor for form schemas.
11. **Twin uses r3f `frameloop="demand"`** with a 2D SVG fallback toggle; landing hero 3D is reduced-motion aware.
12. **Government electricity module** implemented as city grid ops + ADR + disruption alerts, as the prompt §15 prescribes.
13. **Badges, certificates, rewards, field-assistant login, tesseract OCR, PDF export** are not built (prompt marks them stretch/future); report is printable via `window.print()`.
14. **Theme replaced by "Savera Earth"** (supersedes #2 and MASTER_PROMPT §10's always-dark landing) — user instruction on 2026-09-25 to copy the colour combination and fonts of a reference screenshot (cream surfaces, chocolate primary, forest-green accent, mono labels) across the whole project. Light is now the default theme; a warm "Espresso" dark theme uses the same tokens; the landing page follows the theme. Status-tone hues (cyan/green/amber/red/grey) are unchanged, only deepened for contrast on cream.
15. **Fonts: Plus Jakarta Sans + JetBrains Mono** replace Outfit + Inter, with a larger type scale (`text-xs` 13 px, `text-sm` 15 px, `text-base` 17 px, new `text-2xs` 12 px) — user asked for larger, more legible text.
16. **Global restyle edited frozen foundation files** (`globals.css`, `app/layout.tsx`, `components/{ui,savera,layout,charts,maps}`) — a cross-cutting user instruction cannot be done additively. Hard-coded dark classes were converted to semantic tokens by a context-aware codemod (3,410 replacements in 92 files; mapping in `docs/CONTINUATION_PLAN.md`). Feature phases after T return to the add-new-files rule.
17. **Solid amber/rose action buttons became the brown primary** (LPG pages, alert publisher, ADR create) so every screen has one primary action colour, as in the reference. Stream colours remain for icons, tints and charts; the voice assistant's red "recording" state stays red as a status signal.
18. **Landing v3 structure (Phase L) supersedes spec 01 §3's section order.** User instruction on 2026-09-25 to model the landing on a reference screenshot (centred two-line hero, golden-path steps, two-layer protocol cards, "lifeline" phone mock-up, tech cards, big CTA) and to add Problem → Solution → Innovation → Impact sections with financial savings in the hero. Colours/typography stay Savera Earth (structure copied, palette not). The 3D house remains as a "stage" under the hero copy; "What SAVERA does", "The loop" and the Connected Layer are folded into the Solution / Innovation / Tech sections so no product truth is lost. Impact numbers come from a new pure engine module `lib/engine/impact.ts` (slab-aware ₹ savings under the demo tariff, 8–12 % band, 5,000 seeded households, CEA grid factor) and are always labelled `Estimated · illustrative`.
19. **First-run guided setup gates `/citizen/electricity` once per user.** A persisted `useOnboardingStore` (`savera-onboarding-v1`) records completed/skipped per user id; `useFirstRunGate` redirects first-time citizens to `/citizen/onboarding`. MASTER_PROMPT §2.3 ("never block") is honoured: every step has Skip for now / Set up later and the welcome step offers "Skip setup — explore with demo data". "Reset Demo" clears the store so personas become first-time again for presentations. The gate is only on the electricity dashboard (the account's default landing), not on the whole citizen layout, so deep links keep working.
20. **Bill uploads open the real OS file picker; extraction stays simulated.** `features/bills/BillDropzone` accepts images/PDFs (click, keyboard or drag-and-drop), previews the file locally (object URLs, never uploaded) and then runs the existing `simulateOcr` behind a staged scanning animation. Extracted values remain the spec anchors (390 kWh / ₹3,120) so the demo story holds; the chip reads `Simulated OCR`. A "Use a sample bill" path keeps demos fast without a file. The gas setup's PNG bill field is a ₹ amount, so it deliberately has no picker (the simulated extraction returns electricity values).
21. **Phase L touched two frozen files additively**: `components/layout/ResetDemoButton.tsx` (also resets the onboarding store) and `components/layout/PortalShell.tsx` (`animate-fade-up` on `<main>`); the electricity dashboard and wizard were edited region-locally for the gate and the file picker. Everything else is new files.
23. **Smart Gas & PNG/LPG Metering System, 3D Spatial Network Twin, and Automated Safety Protocols.** Implemented end-to-end City Gas Distribution (CGD) and smart LPG telemetry:
   - **Data Model & Engine (`src/types/gas.ts` & `src/lib/engine/gas.ts`)**: Defines smart meter telemetry (flow in SCMH and LPG kg/h, line pressure in mbar, cumulative SCM volume, ambient methane PPM, valve status, LoRaWAN signal, battery health). Pure calculation functions evaluate micro-leaks (< 0.045 SCMH trace flow for > 3.5 hrs), critical burst fractures (> 1.6 SCMH with pressure collapse < 12 mbar), and unattended continuous burners (> 180 mins).
   - **3D Interactive Gas Network Simulation (`src/components/gas/GasNetwork3D.tsx`)**: Three.js WebGL physical simulation modeling City Gas Regulating Station (DRS Skid with Emerson/Pietro Fiorentini regulators and Mercaptan odorant dosing), underground yellow PE-100 gas mains, building service riser with secondary regulator, smart solenoid emergency shut-off valve (250ms trip time), household smart ultrasonic gas meter (Itron Gallus / Pietro Fiorentini RSE with LoRaWAN and optical tamper sensor), Sensonic IoT cylinder tare scale, kitchen brass manifold, smart dual-burner stove with animated 3D flame particles (clean stoichiometric blue flame, lazy yellow incomplete combustion flame, extinguished flame during cutoff), NDIR methane sniffer, and instant gas geyser. All 3D components are clickable via raycasting, opening hardware spec sheets and real-time telemetry controls.
   - **Gas Supply, Consumption & Anomaly Simulator (`src/components/gas/GasSupplyAnomalySimulator.tsx`)**: Integrates 5 interactive demonstration scenarios (Normal Consumption, Trace Micro-Leak, Line Rupture Auto-Trip, Tamper/Signal Delay, Verified & Re-Armed), baseline quota and regulator pressure setpoint sliders with historical continuity retention, emergency remote valve cutoff, automated 30-second static line pressure decay integrity test modal (verifying 0.00 mbar drop before valve re-arm per NFPA 54 / IS 15139), and SCADA telemetry JSON export.
   - **Landing & Cross-Portal Integration (`Hero3D.tsx`, `/citizen/twin`, `/citizen/gas`, `/supervisor/gas`, `/gov/gas`)**: Enhanced landing `Hero3D` with interactive clickable 3D meshes (house, solar PV roof, water tank, electricity/water/gas meters) and floating telemetry popovers; upgraded `/citizen/twin` to a 3-way utility switcher (`⚡ Electricity Micro-Grid`, `💧 Water SCADA & Losses`, `🔥 Gas & LPG Network`); added view switchers across citizen, supervisor, and government gas dashboards.
24. **Real 3D Physical Micro-Grid SCADA Simulation for Electricity (`ElectricityNetwork3D.tsx`).** Replaced the 2D HTML/CSS schematic grid with a true Three.js WebGL physical 3D model simulation matching the visual fidelity of `WaterNetwork3D`:
   - **Generation & Grid Layer**: 11 kV / 415 V Municipal Distribution Substation Step-Down Transformer (ABB/Siemens 500 kVA) with cooling fins and high-voltage ceramic insulators.
   - **Rooftop Solar PV Array**: 3.2 kWp Monocrystalline PERC array tilted at 15° with Fronius Primo GEN24 inverter generating 2.4 kW.
   - **Transmission & Flow**: Overhead low-tension drop line with flowing amber electrical energy particles reflecting real-time active load and frequency.
   - **Smart Metering & Protection**: L&T / Schneider Electric Bi-Directional Smart Net Energy Meter (DLMS/COSEM, LoRaWAN, pulse LED blinking proportionally to active kW) and Hager MDB panel.
   - **3D Architectural Habitat**: Transparent multi-level structure with physical 3D appliances (Split AC with thermal aura and spinning fan, rotating Ceiling Fans, architectural LED downlights, Inverter Refrigerator, Storage Geyser, OLED TV, Front-Load Washer, Booster Water Pump, and EV Wallbox Charger).
   - **Raycasting Interactivity**: All 3D components are clickable, opening the specification drawer with live telemetry and direct power / setpoint actuators that update `twinStore` dynamically.


25. **HACKFINIX 2026 credit is a first-visit splash plus an always-available badge, not a permanent banner.** User instruction on 2026-09-25 to add a popup saying "Made for HACKFINIX 2026, Cambridge North Campus, Bangalore". `features/hackathon/HackfinixSplash` opens once per browser session on the landing page (sessionStorage flag `savera-hackfinix-splash-seen`, dismissable by button, overlay or Esc, auto-focus suppressed so the hero is not jumped). `HackfinixBadge` (pill in the landing footer and auth footer, compact in every portal sidebar) reopens the same dialog so judges can find the credit from any screen without it competing with the product UI. Event text lives in one `HACKATHON` constant.
26. **Final UI/UX pass touched frozen chrome files additively.** (a) `PortalShell` gains a phone bottom tab bar (`layout/MobileTabBar`, four primary destinations per role + "More" → drawer) and bottom padding; the voice FAB and panel sit above it below `lg`. Spec 01 §7 asked for a citizen tab bar; it is applied to all three portals because supervisor/gov are also demoed on phones. (b) `ui/tabs` `TabsList` now `justify-start` with a hidden scrollbar — a centred, overflowing flex list cannot scroll to its first tab, which hid "Overview" on phones. (c) `layout/RouteProgress` (root layout) shows a 3 px brand progress bar during client navigation so cold-compiled routes in `npm run dev` feel responsive. (d) `next.config.ts` sets `devIndicators: false` so the dev bubble does not overlap the sidebar footer / tab bar during demos. (e) All `PageHeader` badge wrappers, KPI/section header rows with chips, and segmented controls (`/gov`, `/citizen/scan`, `/citizen/twin`) wrap or collapse to grids below `sm`/`md`, eliminating every horizontal overflow found by a 49-route 390 px scan.
27. **Nine pre-existing ESLint errors in the 3D twin files were fixed** (prefer-const in `GasNetwork3D`, `GasSupplyAnomalySimulator`, `WaterNetwork3D`; explicit `any` in `DigitalTwinView`, `ui/Chips`, `stores/twin`) so `npm run lint` is back to 0 errors. The remaining 407 warnings are unused-variable warnings from earlier phases.
28. **`docs/SAVERA_Architecture_and_Pitch.docx`** is generated from the markdown sources (ARCHITECTURE, MASTER_PROMPT, spec 01–06, DECISIONS, README) with docx-js and is the hand-off document for the HACKFINIX jury: flows, architecture, pitch script, judge Q&A and the production checklist.
