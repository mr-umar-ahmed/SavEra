# DECISIONS.md — deviations from `docs/MASTER_PROMPT.md` and notable choices

Format: **Decision** — reason. (Date: 2026-09-25 unless noted.)

1. **Spec files `docs/spec/01…06.md` were not supplied.** The master prompt (§5–§11) is used as the sole screen-level source of truth; concise derived spec files are authored in `docs/spec/` from the prompt so the referenced structure exists. Where the prompt says "see spec 02", the corresponding prompt section governs.
2. **Previous SavEra app was deleted; only its visual theme was kept** (dark `#050B08`/`#0A0F0D`, emerald primary, Outfit + Inter, glass cards, pill buttons, status accents). This was the explicit user instruction ("use the theme of the folder… override and delete everything").
3. **Next.js 15.5** (prompt target) replaced the previously installed Next 16.1 — fresh `npm install`, lockfile regenerated.
4. **Maps: react-leaflet 5 + OSM raster tiles** instead of MapLibre GL — lighter, no WebGL requirement, simpler dynamic import; the prompt allows either.
5. **shadcn/ui components are hand-authored** on Radix primitives (`src/components/ui`) rather than generated by the shadcn CLI, so tokens map exactly to the inherited theme. API mirrors shadcn.
6. **State model: one persisted Zustand "demo database" (`useDataStore`)** seeded from `buildSeed(demoNow)` plus small session/twin/ui stores, with an async mock API layer over it. Simpler than per-role stores and still swappable for a real backend.
7. **Auth is client-side** (persisted session + `RoleGuard` in each portal layout); no Next middleware, since there is no server session.
8. **`demoNow`** is captured once on the client and persisted; seed dates are relative to it (current LPG cylinder started `demoNow − 18 d`, previous cycles 25 d each; current electricity month = month of `demoNow`). This keeps the spec anchors (18 days used, 350 → 390 kWh) true on any date.
9. **LPG "Area A–D"** in the supervisor screens map to XYZ/ABC/DEF/GHI Colony (codes A–D) so every screen uses the same four Ward 24 areas.
10. **zod v4** (installed latest) instead of v3 — API differences are minor for form schemas.
11. **Twin uses r3f `frameloop="demand"`** with a 2D SVG fallback toggle; landing hero 3D is reduced-motion aware.
12. **Government electricity module** implemented as city grid ops + ADR + disruption alerts, as the prompt §15 prescribes.
13. **Badges, certificates, rewards, field-assistant login, tesseract OCR, PDF export** are not built (prompt marks them stretch/future); report is printable via `window.print()`.
14. **Theme replaced by "Savera Earth"** (supersedes #2 and MASTER_PROMPT §10's always-dark landing) — user instruction on 2026-09-25 to copy the colour combination and fonts of a reference screenshot (cream surfaces, chocolate primary, forest-green accent, mono labels) across the whole project. Light is now the default theme; a warm "Espresso" dark theme uses the same tokens; the landing page follows the theme. Status-tone hues (cyan/green/amber/red/grey) are unchanged, only deepened for contrast on cream.
15. **Fonts: Plus Jakarta Sans + JetBrains Mono** replace Outfit + Inter, with a larger type scale (`text-xs` 13 px, `text-sm` 15 px, `text-base` 17 px, new `text-2xs` 12 px) — user asked for larger, more legible text.
16. **Global restyle edited frozen foundation files** (`globals.css`, `app/layout.tsx`, `components/{ui,savera,layout,charts,maps}`) — a cross-cutting user instruction cannot be done additively. Hard-coded dark classes were converted to semantic tokens by a context-aware codemod (3,410 replacements in 92 files; mapping in `docs/CONTINUATION_PLAN.md`). Feature phases after T return to the add-new-files rule.
17. **Solid amber/rose action buttons became the brown primary** (LPG pages, alert publisher, ADR create) so every screen has one primary action colour, as in the reference. Stream colours remain for icons, tints and charts; the voice assistant's red "recording" state stays red as a status signal.
18. **Landing v3 structure (Phase L) supersedes spec 01 §3's section order.** User instruction on 2026-09-25 to model the landing on a reference screenshot (centred two-line hero, golden-path steps, two-layer protocol cards, "lifeline" phone mock-up, tech cards, big CTA) and to add Problem → Solution → Innovation → Impact sections with financial savings in the hero. Colours/typography stay Savera Earth (structure copied, palette not). The 3D house remains as a "stage" under the hero copy; "What SAVERA does", "The loop" and the Connected Layer are folded into the Solution / Innovation / Tech sections so no product truth is lost. Impact numbers come from a new pure engine module `lib/engine/impact.ts` (slab-aware ₹ savings under the demo tariff, 8–12 % band, 5,000 seeded households, CEA grid factor) and are always labelled `Estimated · illustrative`.
19. **First-run guided setup gates `/citizen/electricity` once per user.** A persisted `useOnboardingStore` (`savera-onboarding-v1`) records completed/skipped per user id; `useFirstRunGate` redirects first-time citizens to `/citizen/onboarding`. MASTER_PROMPT §2.3 ("never block") is honoured: every step has Skip for now / Set up later and the welcome step offers "Skip setup — explore with demo data". "Reset Demo" clears the store so personas become first-time again for presentations. The gate is only on the electricity dashboard (the account's default landing), not on the whole citizen layout, so deep links keep working.
20. **Bill uploads open the real OS file picker; extraction stays simulated.** `features/bills/BillDropzone` accepts images/PDFs (click, keyboard or drag-and-drop), previews the file locally (object URLs, never uploaded) and then runs the existing `simulateOcr` behind a staged scanning animation. Extracted values remain the spec anchors (390 kWh / ₹3,120) so the demo story holds; the chip reads `Simulated OCR`. A "Use a sample bill" path keeps demos fast without a file. The gas setup's PNG bill field is a ₹ amount, so it deliberately has no picker (the simulated extraction returns electricity values).
21. **Phase L touched two frozen files additively**: `components/layout/ResetDemoButton.tsx` (also resets the onboarding store) and `components/layout/PortalShell.tsx` (`animate-fade-up` on `<main>`); the electricity dashboard and wizard were edited region-locally for the gate and the file picker. Everything else is new files.
22. **Multi-Appliance Digital Twin Simulation & Meter-to-Meter Smart Water Supply & Loss Intelligence.** Added `DigitalTwinView.tsx` with live micro-grid telemetry and AI recommendation simulation cards for every single appliance (AC, Geyser, Fridge, Fans, Lights, TV, Washer, Pump, EV Charger). Built the Meter-to-Meter 3D Water Network Simulation (`WaterNetwork3D.tsx` & `WaterSupplyLossSimulator.tsx`) aligning with India's MoHUA smart water automation standards: models physical hardware (Bulk Electromagnetic Meter, Danfoss Pressure Transmitter, DI K9 Feeder, AVK Sluice Valve, WIKA sensors, Kamstrup flowIQ / Sensus iPERL smart meters), implements the Water Balance Engine (Inflow vs Downstream Sum), enforces neutral loss discrepancy terminology ("Requires verification", never unverified confirmed leak), enables water department baseline quota and pressure adjustments with historical continuity retention, and includes 5 interactive demonstration scenarios across citizen and supervisor water portals.
